## Architecture Notes
- Core logic in `content.js` of each version folder; popup (`popup.html/js/css`) alongside. No background service worker.
- Supported sites live in THREE places that must match: manifest `content_scripts.matches`, `SITE_HOSTS` at the top of content.js, and `SITES[].hosts` in popup.js. test-V32 section 28a fails if they drift.
- Test harness: `tests\test-V32.js` — plain node script. Since V32: `video.dispatch` of play/pause/seeked/ratechange first fires a document `keydown` (a real user gesture; `env.noGesture = true` simulates the player acting on its own), `env.stubFor[name]` shares one chrome stub between "tabs", `I.closeTab()` ends one tab, `env.perfFor[name]` gives a page age. Since V31 every fake tab sits on the same title (`/watch/80000001?wt=<name>`; `env.locFor[name]` overrides, `location.assign` records into `env.navs`); `runPopup(url, store, fetchImpl)` (offline by default). `env.FakeWS = makeFakeMqtt(env)` wires an in-memory MQTT broker (section 32 backup-route tests; real WebCrypto in the vm). Per-instance `makeInstance(env, name, preset, host, src)` (src = another build's content.js, e.g. V25 for mixed-version tests) seeds storage pre-boot (host defaults to `www.netflix.com`). `runPopup(url, store)` runs the real popup.js against a fake DOM built from popup.html ids.
- Version alignment rule: manifest version == EXT_VER badge string (currently 1.32.0).
- Release extras (since V31): update `latest.json` (version, zip URL, notes) and copy the new zip to `wt-latest.zip` in the repo root — the popup update notice and the in-party update link read those.
- **Before shipping, run the real-Chrome end-to-end test** `node tests\rig\e2e.js --build <folder>` (44 checks since V32: + S13 catalogue trailers, S14 reload mid-episode; since V31: + S11 follow-the-friend with a real page load, S12 real buffering both ways; earlier: connect, play/pause/seek/speed sync both ways, chat, voice, reloads, link drop, PeerJS server down, guest-first). The fake harness's `<video>` never fires events on its own and its links never die silently — the e2e test is what found the V29 sync and reconnect bugs.
- **Audio changes must be measured on the real-Chrome rig** (`tests\rig\`, `node tests\rig\matrix.js <build>`), not only the fake harness: the fake harness cannot hear. Echo cancellation itself cannot be measured there (no acoustic path) — only that it is enabled and does not degrade speech.

## Conventions & Gotchas
- Fake DOM elements use `.tag` not `.tagName` — always check both (`e.target.tagName || e.target.tag`).
- `dispatchDoc` on fake doc calls handlers via stored listener array; fake events need `preventDefault` wrapped in try/catch.
- Opus SDP must match mic capture: mono mic → `stereo=0` in SDP. Never set stereo=1 with mono capture.
- `position: fixed` elements don't automatically appear in fullscreen — must reparent into fullscreen container.
- In the harness, a lone HOST cannot acquire the mic — pair a guest first.
- Voice-line rules: mute ≠ close; answer always carries a slot; never redial while a line is healthy. `attachVoiceCall` hot-swaps the mic IMMEDIATELY (redial fallback) — PeerJS `MediaConnection` never emits `"open"`, so never defer to it and never gate `toggleMic` / `ensureMicIfWanted` on `callOpen` (that was the V19/V20 total-voice-failure bug, fixed in V21). The 5s debounce in `requestVoiceRedial` prevents redial storms. `replaceTrack` is async — always await it before reading `sender.track` (V26). Echo cancellation stays ON with NC (V28) — do not turn it off again to chase "beeping"; that was the redial storm.
- Both sides must run the same version when testing voice fixes (user + friend were once on V21 vs V22).
- Status strings during outages stay calm/stable.
- Buffering: drift correction and the re-sync safety net must stand down while either side buffers (`buf`/`hold` flags) — positions are frozen on purpose (V31).
- Follow-the-friend: only navigate to origin+path on SITE_HOSTS; never carry the friend's query string (V31).
- Rig media: the e2e server must honour Range requests for `stall.wav`, otherwise Chrome restarts the download from 0 and the clip jumps back — it looks exactly like an extension bug.
- Sync events: never ignore video events by time window — only the exact change we applied (`expectEcho`), or real clicks get lost (V30).
- The PeerJS server is only needed to START a link; never treat its errors as a broken party while `isOpen()` (V30). Never refuse a friend's re-dial because we "still have" a link — it is probably dead (V30).
- The friend's display name in real sessions is **Megha** (Priya in old notes/tests).
- Bar input (`#wt-qtype-input`) is separate from overlay input (`#wt-qtype-overlay-input`). Tests must use correct IDs.
