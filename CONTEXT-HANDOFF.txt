1. WHAT THIS PROJECT IS
-----------------------
A personal Chrome extension (Manifest V3) that lets two people (Sourav = usually
host, friend Priya = usually guest) watch the same streaming episode in sync,
with chat, emoji reactions, floating messages, watch history and a live voice
call. Peer-to-peer over WebRTC via PeerJS (lib/peerjs.min.js, v1.5.4); no own
server. Optional "Direct connect" mode exchanges codes by hand when the PeerJS
cloud signaling server (0.peerjs.com) is blocked.

Supported sites only (since V24): netflix.com, hotstar.com, jiohotstar.com,
primevideo.com, jiotv.com, jiocinema.com.

--------------------------------

V29 = V28 + one change: auto-level target VB_TARGET_RMS 0.07 -> 0.13
(about -17.7 dBFS). Reason: the full rig matrix showed V28 played a normal /
AGC-levelled voice about 4 dB QUIETER than V27 (V27's compressor makeup gain
had been lifting voices over the movie). Wrong direction for a user who says
the friend is faint.

What V29 does for voice (cumulative from V26-V29):
a) Voice call setup goes over the existing data link ("voffer", "vanswer",
   "vice", "vbye" messages), not through the PeerJS cloud server. Works when
   ad blockers / Wi-Fi blips kill the PeerJS server, and works in Direct mode.
   Friends older than 1.26 (detected from the "hello" message version) still
   get the legacy PeerJS media call.
b) Echo cancellation + noise suppression + auto gain all ON by default, all
   controlled by the one NC (headphones) button. NC off = raw mic.
   Chrome cannot switch echo cancellation on a live mic, so toggling NC
   re-acquires the mic and hot-swaps it onto the same call (no redial).
c) Opus codec forced to 64 kbps VBR, mono, in-band FEC, no DTX (SDP munge).
d) The friend's voice plays through Web Audio:
   source -> gain (auto-level x manual slider) -> peak limiter -> makeup-gain
   undo -> speakers. The hidden <audio id="wt-remote-audio"> keeps the stream
   (Chrome only feeds remote WebRTC audio to Web Audio while an element holds
   it) and is muted while the graph runs; if the AudioContext is suspended
   (no click yet) the element plays instead, and any click resumes the graph.
e) Auto-level: measures the friend's speech level every 100 ms. Noise floor =
   10th percentile of the last 5 s. Speech = at least +16 dB over the floor
   and above -58 dBFS for 2 ticks in a row. Gain -> target / level, x1..x16,
   but the boosted noise floor is never lifted above about -54 dBFS. Silence
   and room noise never raise the gain. One-time chat note
   "<name>'s mic is quiet - auto-boosting their voice" at x2.5 or more.
f) Volume slider in the panel: 0-200% (saved as wt_voice_vol).
g) Movie ducking: while the friend talks the video volume drops to 40% of
   its value, comes back after 0.9 s of silence to the EXACT previous value.
   If the user/site changes the volume meanwhile, ducking stops touching it.
   Muted or paused movies are left alone. Leaving the party restores it.
   (S.duckOff = true disables it; there is no UI switch.)
h) Self-heal: the host's heartbeat re-dials a voice line that failed/closed or
   produced no audio for 15 s (8 s guard).
i) Mic swap awaits replaceTrack() (fixed the old "redial storm").
j) Specific mic error messages (blocked for the site / no mic / mic busy in
   another app) and a hint if the permission prompt is pending > 2.5 s.

8. HARD-WON RULES / GOTCHAS
---------------------------
- PeerJS MediaConnection NEVER emits "open". Never defer anything to it and
  never gate toggleMic / ensureMicIfWanted on a "call open" flag (V19/V20
  total voice failure).
- replaceTrack() is async; Chrome updates sender.track only after it
  resolves. Always await before checking (V18-V21 "redial storm", garbled /
  beeping voice).
- Keep echo cancellation ON with NC. It was turned off in V19 to "fix
  beeping" - the beeping was the redial storm. EC off = echo + movie leak on
  laptop speakers.
- Voice-line rules: mute != close; the callee always answers with an audio
  slot (silent track if mic off); host always dials; never redial a healthy
  line; requestVoiceRedial has a 5 s debounce.
- Opus SDP must stay stereo=0 to match the mono mic.
- Chrome's DynamicsCompressor adds automatic makeup gain (0.6 x reduction at
  0 dBFS) - V28+ cancels it with a gain node (LIM_MAKEUP_UNDO).
- Remote WebRTC audio reaches Web Audio only while a media element holds the
  stream - keep #wt-remote-audio attached (muted).
- PeerJS connect() returns undefined (no throw) when its server is
  unreachable - guard it.
- Direct mode: never close S.directPC while the link is up; the data channel
  is already open when finishLink runs, so call onConnOpen() manually.
- position:fixed UI must be re-parented into the fullscreen element.
- Fake DOM uses .tag not .tagName; fake events need preventDefault in try.
- In the harness a lone host cannot get a mic - pair a guest first.
- When writing node one-liners in Git Bash, Windows paths with backslashes
  and \u escapes get mangled inside heredocs/templates - use the Edit tool.
- Both people must run the same (latest) version when judging voice fixes.
